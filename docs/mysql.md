# さくらでSQLiteからMySQLへ切り替える

1. さくらのサーバーコントロールパネルで名刺アプリ専用の**空のMySQLデータベース**を作成し、DBサーバー名、データベース名、ユーザー名を確認します。
2. サーバー上の `/home/gourd/trail-card-private/config.php` の戻り値の配列に次を追加します。接続情報はこの非公開ファイルだけに設定します。既存の `identity_key`、`providers`、`data_dir` はそのまま使います。

```php
'mysql' => [
    'host' => 'コントロールパネルに表示されたDBサーバー名',
    'database' => '作成したデータベース名',
    'user' => 'DBユーザー名',
    'password' => 'DBパスワード',
],
```

3. Web版とCLI版のPHPで `pdo_mysql` を有効にします。初回移行のCLIには `pdo_sqlite` も必要です。利用者の更新を止め、処理中の保存が終わった時間帯に GitHub Actions のデプロイを main から新規実行します。事前に手動でテーブルを作る必要はありません。
4. デプロイは接続先の空き状況を確認し、メンテナンスに入って旧版のバックアップを採取します。全テーブルを親から順に取り込み、件数を検証し、完了印を同じトランザクションで保存します。以後はMySQLに読み書きし、残っているSQLiteファイルを再取り込みしません。
5. 同じブラウザーで以前の名刺、交換相手、会った記録、画像、Google連携状態を確認します。画像・セッション・バックアップは引き続き非公開の `data_dir` にあります。

## バックアップと復元

`php /home/gourd/trail-card-private/bin/backup.php` は一貫した読み取りトランザクションで全テーブルを取得し、非公開の `data/backups/日時-乱数/` に `data.sql`、参照画像、設定を書き出します。`.partial` は未完了です。

復元時はアクセスを止め、別途作った空の専用DBに以下を実行します。パスワードはプロンプトで入力します。

```sh
mysql -h DBサーバー名 -u DBユーザー名 -p 新しいDB名 < data.sql
```

同じバックアップの画像を `data_dir/images/` に戻し、元の `identity_key` を維持した設定で接続先を復元先DBに切り替えます。セッションを破棄し、名刺・交換相手を確認して公開を再開します。

初回移行失敗時は503のまま原因を確認し、deploy/README.md に従って旧コードを復旧します。旧SQLiteは保存されています。再度移行するときは空の専用DBを選びます。MySQLで公開を再開した後の変更は旧SQLiteには反映されません。
