# デジタル名刺アプリのやることリスト

優先するのは「投稿者同士でつながる」「会った人を思い出せる」「自分の名刺を見せる」の順。視聴者やイベント参加者も利用できる。以下の順序は作業順の案。

## 1. 本番で確認する

- [x] MySQLへの切り替え状況を確認する。未反映なら[移行手順](mysql.md)で切り替え、以前と同じ端末で名刺・交換相手・履歴・画像を確認する。
- [x] [Google連携](google-auth.md)を実アカウントで確認する。別ブラウザーから連携済みの名刺に復帰できれば完了。
- [ ] iPhoneとAndroidで初回のQR交換、再会の記録、過去のメモへの追記を一通り試す。メモが相手に表示されないことも確認する。

## 2. 圏外での対面交換（既定の優先改善項目）

- [ ] 双方がQRを読み取る手順と、圏外で渡す最小限の名刺情報を決める。
- [ ] 交換を端末に仮保存し、通信復帰後に確定する。片方だけ読み取った場合や、同じ交換を再送した場合の扱いを検証する。

## 3. GPS近接による自動交換（採用案・未実装）

- [ ] 「交換」画面から任意で開始・終了する。初期値はOFF。双方がオンラインで画面を開き、自動交換を有効にしている間だけ対象とする。初案は15分で自動終了。
- [ ] 距離・測位精度・近くにいた時間の条件を決める。屋外の集合場所と混雑した会場で試し、離れた相手との誤交換、近くにいる相手の検出漏れを確認する。
- [ ] 初対面なら双方の名刺帳に登録し、交換済みなら双方に再会履歴を1件追加する。同じ場所に居続けた場合や通信を再試行した場合も重複させない。
- [ ] 照合用の位置情報に短い有効期限を設け、期限後に削除する。相手に座標を表示せず、履歴にGPSを残す設定は独立させる。
- [ ] 位置情報の許可拒否、画面ロック、通信断、手動終了、時間切れで古い位置が照合に使われないことを確認する。

## 4. チェックポイントの訪問記録

- [ ] あらかじめチェックポイントを設定し、利用者が現地に到着したときに、その地点を訪れたことを記録できるようにする。聖地巡礼のスタンプラリーや、公開動画で紹介された場所を訪れた記念に使えるようにする。

## 5. 名刺帳のスワイプ閲覧

- [ ] 名刺帳で名刺を開いた状態から、左右にスワイプして前後の名刺を閲覧できるようにする。

## 実装済み（GitHub main）

- 仮ユーザーの発行と端末Cookieによる再訪、任意のGoogleアカウント連携
- 名刺画像またはテンプレートの表示、トップページの交換用QR
- オンラインでのQR交換と承認、交換済みの相手との再会記録、私的メモの追加・編集、任意のGPS記録
- PHP・MySQLでの保存、旧SQLiteからの移行、バックアップ、GitHub Actionsからの手動デプロイ

## 保留

- X連携の本番有効化は利用料金と需要を見て判断する。ニコニコ認証は初期対象外。
- イベント共通QR、圏外の位置履歴の事後照合、ネイティブアプリでのBluetooth交換は、GPS近接交換とは別の候補として保留する。
